# 액센트 스케일 눈 평가 (정성)

> 2026-07-26 시작. 벤치마크(ΔE, `accent-scale-bench-report.md`)가 "레퍼런스를 얼마나
> 흉내 냈나"를 재는 것과 달리, 여기서는 **눈으로 봤을 때 어떤 알고리즘의 어떤 구간이
> 좋은가/나쁜가**를 기록한다. 이 관찰이 종합 단계("우리 곡선",
> `accent-scale-derivation-track.md`)의 1차 근거가 된다.
>
> 평가 도구: `web` 랩 (`#lab`). 프리셋 버튼(아래 hue 세트와 동일)으로 입력을 바꿔가며
> 알고리즘 5종 + nearest references를 나란히 비교한다.

## 평가 방법

1. 랩에서 프리셋(또는 임의 색)을 선택한다.
2. 각 알고리즘 줄을 **관찰 포인트** 기준으로 훑고, 아래 hue별 표에 관찰을 적는다.
   - 좋은 점보다 **거슬리는 점**을 우선 기록 (탈락 사유가 설계 결정을 만든다).
   - 반드시 레퍼런스(tailwind/radix 줄)와 비교해서 "손튜닝은 여기서 뭘 다르게 했나"를 본다.
3. hue를 다 돌고 나면 말미의 **알고리즘별 종합**에 패턴을 정리한다.

## 관찰 포인트

| 포인트 | 무엇을 보나 | 알려진 위험 |
| --- | --- | --- |
| 밝은 끝 (1~3) | 배경색으로 쓸 만큼 옅은가, 색끼가 남아 있나 | 밋밋한 회백색 vs 과채도 파스텔 |
| 어두운 끝 (끝 2~3칸) | 탁해지거나 검정으로 뭉개지지 않나, 색 계열이 유지되나 | 노랑·주황이 갈색/탁색으로 |
| 단계 간격 | 이웃 칸끼리 간격이 고른가, 특정 구간에서 점프하나 | 앵커 주변 뭉침 |
| 채도 곡선 | 중간이 가장 쨍하고 양 끝으로 자연스럽게 빠지나 | 끝까지 쨍해서 부담스러움 |
| hue 유지 | 밝기가 변해도 같은 색 계열로 보이나 | 파랑→보라 드리프트 |
| 앵커 자리 | 입력색(링 표시)이 스케일 흐름에 자연스럽게 앉나 | 앵커만 튀어 보임 |

## 알고리즘별 종합

hue별 관찰을 다 모은 뒤 작성. "우리 곡선"에 가져갈 것 / 버릴 것을 명시한다.

**초안 (2026-07-26, 1차 관찰 10/11 hue 기반 — 빨강 미평가):**

| 알고리즘 | 강점 (가져갈 것) | 약점 (버릴 것) |
| --- | --- | --- |
| v1 | 어두운 쪽 단계 분리 (보라에서 최상급) | 끝단 채도 과다(파랑); 웜톤(주황·노랑)에서 액센트와 동떨어진 팔레트 — 고정 L 사다리가 입력 L을 무시하는 구조적 한계 |
| naive | 앵커 보존; 파스텔 앵커 대응; 노랑에서 어두운 과대 없음 | 밝은 끝이 탁하고 이질적(파랑); 시안에서 명도가 죽음 — 흰색으로의 직선 보간이 손튜닝의 밝은 끝 처리를 못 따라감 |
| HCT | 액센트 반영감(파랑); 시안 명도 유지; 어두운 쪽 분리(보라) — 1차 관찰 종합 최상위 | 초록 2번 튀는 색; 노랑 어두운 과대 |
| Leonardo | (1차 관찰에서 강점 없음) | 밝은 끝 탁함(파랑·뮤트); 전반적으로 어두움; 딥에서 단계 차이 소실 |
| Radix | 1–8 다단계 표현의 다양함; 파스텔 대응; 노랑 어두운 과대 없음 | 짙은 쪽 차이 부족(파랑); 딥에서 밝은 쪽 과밀 |

**패턴 (초안):**

- **어두운 끝 간격**이 가장 자주 갈리는 축 — 잘하면 v1/HCT(보라), 못하면 Radix(파랑)/Leonardo(딥)/전원(초록). "우리 곡선"은 어두운 구간의 L 간격 설계가 1순위 과제.
- **밝은 끝 탁함**이 두 번째 축 — naive/Leonardo 공통 약점, 손튜닝(tailwind)은 밝은 끝에서도 색끼를 유지. 밝은 끝의 채도 하한 처리가 필요하다는 신호.
- **웜톤(주황·노랑)은 고정 사다리 계열의 무덤** — 입력 L을 무시하는 설계(v1·HCT·Leonardo)가 여기서 무너지고, 앵커 보존 계열(naive·Radix)이 버텼다. 앵커 L 존중이 필수 요건으로 승격.
- **저채도·극단 L 앵커(뮤트·파스텔·딥)는 전원 애매** — 알고리즘 후보군 밖의 문제. 가이드드 빌더에서 후보 다양화로 풀 영역일 가능성.

## 레퍼런스에서 배운 것 (손튜닝 vs 알고리즘)

눈 비교 중 "tailwind/radix는 여기서 이렇게 다르게 했더라"를 모으는 곳.

- 시안: tailwind는 밝은 명도를 살려두는데 나이브 보간은 명도가 죽는다 — 손튜닝은 시안 계열에서 L을 후하게 배치.
- Radix의 "액센트 = step 9" 설계는 1–8을 배경·상태·테두리용으로 다양하게 쓰게 해준다 — 대신 짙은 쪽(10–12)의 표현 폭이 좁다. 앵커를 스케일 후반에 두는 설계의 트레이드오프.
- 웜톤의 어두운 stop에서 tailwind는 hue를 주황 쪽으로 크게 튼다 (800~950 기준 yellow -22~-28°, amber -20°, orange -8°) — 어두운 노랑=올리브가 되는 지각 현상을 피하는 손튜닝 기법. 평균 Δh가 ~0으로 보였던 건 쿨톤과 상쇄된 착시였다.
