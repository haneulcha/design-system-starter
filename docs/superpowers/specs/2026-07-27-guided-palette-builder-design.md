# 가이드드 팔레트 빌더 — 설계 스펙

> 2026-07-27 승인. 연구 트랙(`docs/research/accent-scale-derivation-track.md`)의 최종
> 소비자 — Refactoring UI의 "accent → 양끝 → 중간" 선택 순서에 우리 곡선 v0를 후보
> 생성기로 얹어, 사용자가 자기 취향의 액센트 스케일을 **배우면서 만드는** 도구.
> [[project-identity]]의 "취향 knob + 교보재" 직결.

## 목적과 성공 기준

- 사용자가 브랜드 컬러 하나에서 출발해 5번의 의미 있는 선택으로 11-stop 액센트
  스케일을 완성한다. 각 선택지는 "무엇이 어떻게 다른가"를 설명해 취향이 **학습**되게 한다.
- 성공 기준: (1) 5단계 완주 플로우가 동작하고 hex 내보내기까지 이어진다,
  (2) 어느 시점에 이탈해도 곡선 자동 채움으로 완성 스케일이 항상 존재한다,
  (3) 엔진 불변식 계약 테스트 전체 통과.

## 아키텍처

```
src/lab/accent-scale/builder.ts     ← 엔진 (순수 함수, 신규)
  Pin = { index: 0..10, color: Oklch }
  BUILDER_STEPS                      // [5, 0, 10, 3, 7] = 500→50→950→300→700
  fillScale(pins): Oklch[]           // 고정점 사이를 곡선 워프로 채운 11-stop

web/src/builder/BuilderPage.tsx     ← UI (신규)
  App.tsx: hash === "#builder" 분기 한 줄

```

- 엔진은 `src/lab/accent-scale/`에 둔다 — `ours.ts`의 OURS_CURVE를 공유하는 같은
  연구 계열이고, 랩 격리 규칙(generator에서 import 금지, 브라우저 번들 안전: 정적

- 상태는 BuilderPage의 React state(`pins`, 현재 단계)뿐. 저장 없음 (YAGNI).
- `ours.ts`는 그대로 둔다 — 랩 비교 줄 유지. 빌더 구현 후 fillScale(단일 앵커)와의
  동치를 테스트로 묶는다.

## 엔진 상세

### fillScale — 다중 고정점 워프

인접 고정점 (i, j) 사이의 stop k (i < k < j):

- **L**: 기준 곡선 진행률 보간 — `t = (Lc[i] − Lc[k]) / (Lc[i] − Lc[j])` (Lc =
  OURS_CURVE의 L), `L_k = L_i − t · (L_i − L_j)`. v0 워프와 동일 수학의 구간 일반화.
  고정점 L이 단조이면 결과도 단조.
- **C**: 곡선 cMult 모양 유지 + 양끝 보정 — 고정점에서 실제 채도와 일치하도록
  보정 계수를 구간 안에서 선형 보간해 곱한다.
- **H**: 고정점 hue의 원형 최단거리 선형 보간. 다중 고정점에서 hue 드리프트가
  자연 지원됨 — 950에서 골드로 틀면 700~900이 그 사이를 잇는다 (tailwind 웜톤
  기법이 별도 장치 없이 들어옴).
- 경계: 고정점이 앵커(index 5) 하나면 fillScale ≡ 우리 곡선 v0. 첫/마지막 고정점
  바깥 구간은 곡선 끝값(OURS_CURVE[0], [10])을 가상 고정점으로 사용.
- 모든 반환 색은 sRGB gamut으로 채도 클램프 (엔진 책임 — UI에는 표시 가능한 색만).
  주의: `ours.derive`는 클램프하지 않으므로(표시 계층에서 클램프) v0 동치 비교는
  "derive 결과에 같은 클램프를 적용한 값" 기준이다. pin 색은 UI가 표시 가능한
  색만 공급하므로(피커 스냅·후보 클램프) 항상 in-gamut으로 가정한다.

### candidatesFor — 단계별 후보

후보 색 = "현재 pins 기준 fillScale이 그 stop에 주는 기본값"에서 해당 축만 변주.
이미 고른 선택과 항상 정합.

| 단계 | 변주 축 | 후보 (라벨) | note 골자 |
| --- | --- | --- | --- |
| 50 | 색끼 cMult 0.05 / 0.092 / 0.18 | 중립적 / 균형 / 색이 드러나는 | 배경에 브랜드 기운이 얼마나 비치는가 |
| 950 | 깊이 L + 웜톤 hue | 기본 (L .278) / 더 깊게 (L .22) / 웜톤: 골드 −25° · 쿨톤: 얕게 (L .32) | 어두운 노랑은 hue를 안 틀면 올리브가 된다 (모든 후보 L은 앵커 L − 0.01로 상한 — 어두운 앵커 역전 방지) |
| 300 | 채도 cMult .55 / .689 / .83 | 차분한 / 균형 / 쨍한 | 호버 배경·태그가 사는 구간 |
| 700 | 채도 cMult .75 / .872 / .97 | 차분한 / 균형 / 쨍한 | 텍스트로 쓰일 때 고채도는 피로 |

- 웜톤 판정: 앵커 hue ∈ [30°, 110°] (OKLCH). 상수는 엔진에 명시, 눈으로 조정 가능.
- 퇴화 처리: 클램프로 후보끼리 같아져도 숨기지 않는다 — "이 앵커에선 이 축의
  선택지가 없다"가 교보재 정보. note에 표시.

## UI 플로우

한 화면 위→아래 누적형 — 완료 단계는 한 줄 요약으로 접히고 현재 단계가 아래 열린다.
"지금까지의 선택 → 스케일 변화"가 항상 보여야 취향 학습이 된다.

- 헤더: 진행 표시 (● ● ○ ○ ○, 단계명).
- 1단계 (액센트): OklchPicker + hex 입력 (랩과 동일 UX). 확정 → `pins=[{index:5,…}]`.
- 2~5단계: 후보 3개 라디오 — 각 후보에 칩 + note + 전체 스케일 미리보기(11칸,
  fillScale 자동 채움, 고정점 칸은 링). 선택 시 하단 미리보기 실시간 갱신,
  "확정"으로 pin 추가 후 다음 단계 오픈.
- 다시 고르기: 완료 단계로 복귀하되 **이후 단계 선택은 무효화** (전제가 달라지므로,
  단순함 우선).
- 완료 화면: 최종 스케일 + stop별 hex + copy hex(랩 포맷) + "내가 고른 여정" 요약
  (단계별 선택 라벨 나열) + 처음부터 다시.
- 하단 고정 미리보기: 현재 pins 기준 fillScale 스케일 상시 표시.

## 테스트

엔진 계약 테스트 (`tests/lab/builder.test.ts`):

| 불변식 | 내용 |
| --- | --- |
| v0 동치 | pins=[앵커]이면 fillScale ≡ oursAlgorithm.derive에 gamut 클램프를 적용한 값 (stop별 근사 일치, 부동소수 허용) |
| 고정점 보존 | 모든 pin은 결과에 verbatim |
| 단조성 | 고정점 L 단조 → 결과 L 강단조 (프리셋 11종 × 후보 조합) |
| 후보 정합 | 항상 3개, sRGB 표시 가능, label/note 비어있지 않음 |
| 웜톤 분기 | hue ∈ [30,110]이면 950 후보에 드리프트 포함, 아니면 미포함 |
| 순서 무관성 | 같은 pin 집합 → 같은 결과 (순수성) |

UI는 기존 관례대로 Playwright 수동 검증 — 5단계 완주, 다시 고르기, copy hex.

## 에러 처리

엔진에 실패 경로를 만들지 않는다 — 후보는 gamut 클램프 후 반환, hex 입력은 기존
정규식 재사용. UI 방어 로직 최소화.

950 후보 L은 앵커 L − 0.01을 넘지 않는다 (어두운 앵커에서 스케일 역전 방지 — 최종
리뷰 반영).
